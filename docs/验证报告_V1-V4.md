# Typora 工作区扩展验证

目标宿主为本机 macOS 27.3、Typora 2.0.0-beta1。最小验证扩展在 `advanced/ignorance.vault/experiments/`，构建的商店包排除该目录。V3 已通过现有 Advanced 扩展实测。V1、V2、V4 仍需在仅含合成笔记的工作区中安装验证扩展，启用工作区和文档只读权限。

## V1 打开其他工作区文件

| 字段 | 内容 |
|---|---|
| 问题 | 扩展能否打开工作区里的其他文件 |
| 环境 | macOS 27.3、Typora 2.0.0-beta1 |
| 做法 | 打开脚本生成的合成工作区，在 `00-验证.md` 的跳转代码块里点击相对链接及「调用宿主打开命令」 |
| 结果 | 未实测。静态渲染文档明确只允许片段和内嵌图片引用，公开 Worker API 无按路径打开工作区文件的方法 |
| 结论 | 查询结果优先显示相对路径，并保留便于手动寻找的文件名。需要打开源文件的视图以用户手动打开为退路，直达能力待宿主证明后接入 |

[静态渲染及链接约束](https://docs.typora.io/extensions/contributes/fence-renderers#static-mode) · [Worker API](https://docs.typora.io/extensions/worker-api)

## V2 静态 resolver 是否能拿到索引

| 字段 | 内容 |
|---|---|
| 问题 | 静态 fence 渲染能否用 `resolver: true` 从 main 拿到工作区数据 |
| 环境 | macOS 27.3、Typora 2.0.0-beta1 |
| 做法 | 打开 `00-验证.md`，观察静态探针是否收到 Worker 的工作区文件数，并分别导出 HTML 和 PDF |
| 结果 | 未实测。官方 resolver 示例使用互动模式，静态渲染的组合未给出示例 |
| 结论 | 编辑区优先按文档明确支持的互动 resolver 交换数据；导出采用静态快照，宿主无法获取快照时仍可读原始代码块 |

[Resolver 和快照文档](https://docs.typora.io/extensions/contributes/fence-renderers)

## V3 工作线程和详情页存储

| 字段 | 内容 |
|---|---|
| 问题 | main 写入的 `typora.storage` 能否被详情页 `view.storage` 读到 |
| 环境 | macOS 27.3、Typora 2.0.0-beta1 |
| 做法 | 在已安装的 Advanced 中打开独立的合成列表样例，执行「查看列表分支」，切换到「列表大纲」详情页。该命令通过 Worker 写入私有存储，详情页调用 `view.storage.get` |
| 结果 | 通过。详情页读到 `- [x] 星河` 与两层缩进子项。点「选中全部」后，无障碍树显示三行选区。该证据覆盖共享读取，Vault 的评分写入与多窗口仍待独立实测 |
| 结论 | 使用扩展共享存储，按当前文档块 ID 选取视图数据。复习评分由 Worker 原子写入 |

[View SDK 存储](https://docs.typora.io/extensions/view-sdk#state-and-storage)

### Node 本地扫描基线

用生成脚本创建对应规模的合成目录，将 `node:fs` 接到 `scanNotes` 的读文件接口。每种规模测三组。首次扫描从无缓存开始，再次扫描传入上一轮结果的 JSON 副本。计时覆盖遍历、读取、哈希和解析，不包含 Typora Worker 通信、缓存落盘或应用重启。每次均核对文件数和再次扫描的复用数。

| 文件数 | 首次扫描 3 次（ms） | 首次中位数（ms） | 再次扫描 3 次（ms） | 再次中位数（ms） |
|---|---|---:|---|---:|
| 1,000 | 82.20 / 56.56 / 52.62 | 56.56 | 38.35 / 38.98 / 30.77 | 38.35 |
| 3,000 | 152.51 / 154.44 / 160.29 | 154.44 | 96.06 / 99.43 / 99.30 | 99.30 |
| 5,000 | 431.26 / 404.57 / 390.67 | 404.57 | 271.53 / 249.42 / 231.21 | 249.42 |

可用 `node scripts/benchmark-vault-scan.mjs` 复跑。脚本输出每轮耗时，并核对文件数与缓存复用数。每次运行会生成独立的临时样例，结束后清理该次生成的目录。
